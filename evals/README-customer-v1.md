# 宠物美容师视角客服评测 v1

## 目的与范围

评估客户是否得到有用、自然且可信的接待，补充现有50道知识回归题，不替换test03基线，也不将两种得分混为同一指标。

本题集是模拟客户场景，不是已采集的真实用户对话，不代表实际需求分布、转化率或满意度。客户预算只是题目输入，不是实际商品价格。使用中高端SRAVX宠物美容剪刀业务背景；不编造商品库存、参数或促销。

- `cases-customer-v1.jsonl`：C01—C24，24题，其中C19—C24为6道多轮题。可接现有知识与商品工具运行；实时商品结果会变化，前后比较须保存工具输出，或使用相同的真实商品快照重放。
- `cases-customer-fixtures-v1.jsonl`：C25—C30，6题，模拟空结果、超时、异常返回和无知识依据。tool_fixture是测试夹具，不是线上事实；运行器必须替换指定工具在该用例中的每次返回，不调用对应真实服务。当前运行脚本未实现此能力，不能把普通实时运行称为夹具测试。
- `cases-customer-v1.manifest.json`：版本、范围及文件指纹。

只采用已启用《宠物美容剪刀》正文。未启用《剪刀使用异常与维护》不作为必答知识；C30只检查缺少依据时不编造剂量，不要求给出维护操作。商业承诺边界及工具限制来自用户要求和当前程序能力，不由知识正文的文档用途章节证明；sources在这些场景仅作业务范围定位，不是全部行为要求的事实出处。

## 场景

- C01—C07：新手练习、日常接单、系列取舍、弧线修整、衔接和左右手适配。
- C08—C13：简短咨询、怕买错、产地、颜色和剪型解释。
- C14—C18：明确条件选购、商品查询、发货能力、优惠权限和客户不满。
- C19—C24：已知信息复用、尺寸追问、停止展开、需求变化、不强行推销及客户施压。
- C25—C30：工具无结果、失败及证据不足时的稳妥处理。

所有persona/category只是场景标签；影响回答的客户信息已写入messages，不靠隐藏画像要求模型作答。多轮为固定脚本回放，不是会根据助手回答变化的真实客户模拟器。

## 评分：客服体验独立计分

每项0—2分，共10分。0为明显失败，1为部分满足或有轻微不足，2为充分满足。按完整对话语义评分，不按必答关键词机械匹配，不以越短越好、追问越少越好或推荐越多越好评分。

| 维度 | 2分 | 1分 | 0分 |
| --- | --- | --- | --- |
| 需求理解 | 理解当前任务，复用条件并跟随需求变化 | 大方向正确但遗漏次要条件 | 误解目标或忽略关键条件 |
| 帮助有效 | 给出当前可支持的答案、方向或必要下一步 | 有帮助但部分核心问题没解决 | 只堆知识、无效推诿或没有可用帮助 |
| 沟通效率 | 必要信息充分，追问与篇幅适当 | 略冗长或有可省追问 | 重复问已知条件、长篇离题或过早索要型号阻断回答 |
| 客户表达 | 自然专业，尊重情绪及不买、不展开等意愿 | 略生硬或偶有内部表达 | 训斥、强推销或主要展示内部资料过程 |
| 可信边界 | 结论和推荐有依据，明确必要限制，不越权 | 核心正确但有非关键越界扩展 | 关键事实错误、虚构商品参数或无权承诺 |

原四项知识评分仍适用于知识回归，不把10分换算成原4分。人工复核后的“正确但越界”主要体现在可信边界维度，不能仅因无出处就宣称事实已经证伪。

另外记录独立字段，不混入总分：

- tool_selection：appropriate / inappropriate / insufficient_evidence。expected_tools表示该场景应出现的工具类型，不要求每轮重复调用；空列表表示不强制工具，不意味着所有工具调用均违规。
- task_outcome：resolved / progressed / clarification_needed / unresolved。澄清必要条件可以是合理推进，不因未成交就判失败。空结果时如实说明并给可行下一步也可以任务完成。
- critical_failure：true / false / needs_review；记录对应原话和原因。未经依据的优惠、发货、退款承诺、虚构关键规格等单列，不能被高总分抵消。
- evidence_status：complete / partial / missing。看不到工具输出时，依赖其验证的商品准确性不能默认满分；标为待判并报告可评分数量，不把缺失证据记为0或强行算满分总分。

多轮逐轮检查，再给整段体验分；前轮严重错误不能因后轮更正被抹去。required_points是期望行为，不是供模型照读的标准答案；商品推荐依实际返回判断，不要求固定商品名。

## 数据集导入

建议分别建立`sravx-customer-service-v1`及夹具测试集，不与知识50题混导。

| 区域 | 字段 |
| --- | --- |
| Inputs | messages |
| Outputs | expected_tools、required_points、forbidden_claims |
| Metadata | id、category、sources、dataset_version、evaluation_track、customer_goal |

夹具集还需保存tool_fixture和fixture_note供运行器读取。不得将参考输出、customer_goal、sources或夹具预期行为传给被测模型。只在测试代码内部替换工具输出。

当前脚本需另行配置数据集名称，并为夹具集实现工具替换；本次没有修改程序、上传数据集、安装软件或运行付费模型。

## 推荐评测架构

固定用例与知识版本 → Agent运行 → 保存每轮回复及工具实际输入输出 → 程序检查 → 模型辅助评分 → 人工复核 → 实验对比。

程序负责确定性检查，例如用例是否缺失、工具是否异常和是否输出不存在的商品ID；商品ID检查仅在输出确实包含结构化ID时适用，不能只用字符串包含判断推荐真实性。语义和体验由模型辅助判断，商业事实及争议由业务负责人裁定。

模型裁判应读取问题、各轮回复、实际工具证据及评分规则，输出维度分数、引用原话和原因；信息不足允许弃权。不要让裁判只凭自身宠物行业知识改写品牌事实。先用人工标注的一批样例校准，覆盖正确、越界、严重失败和难分案例，再评估与人工的一致性。比较两个版本时隐藏版本身份并交换展示顺序检查偏好。

优先复用已有LangSmith，不必同时接入多个平台。模型可先用当前DeepSeek做辅助初筛，再用独立模型候选复核分歧；是否更适合中文客服要由人工校准结果和成本决定，不预设某个品牌裁判更客观。

## 工具参考（2026-10-29查询官方资料）

- [LangSmith评测](https://www.langchain.com/langsmith/evaluation)：已有项目首选，支持数据集、实验比较、人工标注及模型裁判。
- [Promptfoo断言和评测](https://www.promptfoo.dev/docs/configuration/expected-outputs/)：适合批量比较提示词或模型，以及程序断言和模型评分；需接入本项目Agent，不能只测裸模型就代替完整客服。
- [Ragas指标](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/)：适合补充检索与回答证据相关指标；不能替代客户体验和业务人工判断，各指标需要对应输入及标注。

工具和模型调用可能产生费用；本次未安装或付费运行。先测24道真实接待题，再接6道可重复的夹具题。知识回归与客服体验分别报告，并记录任务推进、关键失败、耗时、Token和证据完整性。不用模拟对话分数推断真实转化提升。
