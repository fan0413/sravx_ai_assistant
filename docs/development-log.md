### 学到的内容
- 模型负责理解需求和提出工具调用；程序负责校验与执行查询。
- Harness 是管理模型和工具运行的程序，不等于某一个框架。
- 上架不等于有货；起售价不等于指定规格价格。
- 接口接受参数不代表参数一定生效，需要查看实际实现及功能开关。
- Agent 以消息状态组织调用；工具参数 schema、函数签名和实际请求需保持一致。
- 参数校验必须绑定实际工具入口，仅定义数据类不代表约束已生效。
- 模型客户端初始化、发送请求、Agent 运行和工具执行是不同步骤；只有实际调用才证明对应链路可用。
- 非流式 invoke 与流式 stream 不同；流式模型输出还需要服务端向前端转发才能形成用户端流式体验。

### 关键问题与处理
| 问题 | 处理与结论 |
|---|---|
| 初始化时报 public schema 权限不足 | 管理员在项目库授予项目账号 USAGE、CREATE 后完成初始化，无需超级权限；是否已撤销临时建表权限尚未核实 |

### 技术收获

- HTTP 接口使用 PostgreSQL；独立终端测试仍使用 InMemorySaver，两者的记忆生命周期不同。

## 2026-10-23｜输入校验、异常响应与执行预算

### 本次目标
完善非流式对话接口的输入约束、依赖故障响应和 Agent 执行预算，理解校验、异常与图执行机制的边界。

### 已完成
- 明确采用非流式交互：模型与工具处理完成后一次性返回回答。
- ChatRequest 配置字符串去首尾空白；message 长度为1～1000字符，session_id 为1～100字符。
- 模型客户端配置 timeout=15、max_retries=2。
- 对话接口捕获模型超时返回504，捕获数据库连接及连接池故障返回503。
- 为单次 Agent 调用设置 recursion_limit=12，并处理 GraphRecursionError。

### 关键问题与处理

| 问题 | 原因与处理 | 当前结果 |
|---|---|---|
| 空白输入可能进入 Agent | 字符长度限制不能单独排除纯空格；使用 ConfigDict 去除首尾空白，再由 Field 校验长度 | 已通过响应截图确认纯空白 message 与空 session_id 返回422 |
| 依赖故障只返回笼统500 | 缺少按来源分类的异常响应；分别捕获模型超时、数据库及连接池异常 | 代码已实现504/503映射；模拟和真实故障结果尚未确认 |
| 请求等待时间缺少明确控制 | 模型网络请求未显式设置超时及重试 | 已配置15秒网络超时和最多额外重试2次；仍不代表整个请求的总耗时限制 |
| Agent 可能反复查询不结束 | 图执行缺少显式步数预算 | 设置12步上限并处理超限异常；触发验证未确认 |
| 图步数与工具次数容易混淆 | 多个工具可在同一工具执行步内处理 | 明确步数不能作为精确工具次数或费用限制；后续需要时再使用 Agent 中间件控制 |

### 技术收获
- ConfigDict 提供模型级字符串处理，Field 为字段设置约束；字符数不是 token 数。
- 输入错误422、依赖故障503和模型超时504表达不同情况，不应将所有异常统一误报为超时。
- 当前路由内 try/except 适合逐步学习；多个接口需要共用规则时可考虑全局异常处理器，不强行引入中间件。
- 图执行步是流程调度轮次，不是代码行、聊天轮数或工具次数。同轮多个工具调用可由工具节点在一个图执行步处理。
- 简单模型/工具交替结构中，12步约可支持5轮工具往返及最终回答，仅为估算。
- 每次 invoke 单独计算执行预算，检查点继续保留历史；ReAct 决策不要求开启模型思考模式。

### 验证范围与待办
- 已通过响应截图确认纯空白消息和空会话ID被422拦截；本阶段暂不继续输入边界测试。
- 已学习模型与数据库异常的模拟方法，但尚未确认实际验证结果，不记录为已验证通过。
- 本次依据本地源码及实际运行日志整理文档，未重新调用模型、数据库或执行故障测试。
- 总耗时、精确调用次数、并发和用户身份授权仍需单独设计；session_id 长度校验不等于会话访问控制。

### 下一步
1. 按后续需要验证异常分支、正常请求回归及执行上限行为。
2. 需要精确限制模型或工具次数时，学习并选用合适的 Agent 中间件。

### 技术收获
- 聊天模型生成回答，Embedding 将文本转成向量；创建客户端不等于发送请求。
- def 定义创建方法，调用函数才创建对象；代码读取的配置名称需与环境变量一致。
- embed_query() 处理问题，embed_documents() 处理资料；入库与检索需保持模型和维度一致。
- chunk_size=10 表示每批文本条数，不是每段字符数；关闭客户端长度检查不代表服务端没有限制。
- PostgresSaver 保存会话状态，PGEngine 与 PGVectorStore 服务知识存储和检索，两者用途不同。
- 同步封装内部也可能使用异步连接；异步与流式是不同概念，不保证单次请求更快。
- 修改 Markdown 不会自动更新数据库；分段应保留标题、来源、品牌与更新时间。
