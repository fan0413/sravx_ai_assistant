### 学到的内容
- 模型负责理解需求和提出工具调用；程序负责校验与执行查询。
- Harness 是管理模型和工具运行的程序，不等于某一个框架。
- 上架不等于有货；起售价不等于指定规格价格。
- 接口接受参数不代表参数一定生效，需要查看实际实现及功能开关。
- Agent 以消息状态组织调用；工具参数 schema、函数签名和实际请求需保持一致。
- 参数校验必须绑定实际工具入口，仅定义数据类不代表约束已生效。
- 模型客户端初始化、发送请求、Agent 运行和工具执行是不同步骤；只有实际调用才证明对应链路可用。
- 非流式 invoke 与流式 stream 不同；流式模型输出还需要服务端向前端转发才能形成用户端流式体验。

## 2026-10-20｜商品工具、多轮会话与 FastAPI 接入

### 本次目标

### 关键问题与处理

| 问题 | 原因与处理 | 结果 |
|---|---|---|
| Agent 未正确使用输入或执行查询 | 校正消息状态结构、注册实际工具对象，更新旧阶段提示词 | 日志确认工具执行，终端能延续需求 |
| 对话状态无法延续 | 添加检查点，用 thread_id 关联消息状态 | 同一进程内多轮正常，HTTP 跨请求效果待核实 |
| 服务导入模型失败 | 默认配置查找受启动方式影响 | 根据 model.py 的绝对位置加载 app/.env，完成初始化 |
| 对话接口返回500 | 将 stream() 生成器当作完整状态字典读取 | 非流式接口改用 invoke()，后续3次请求返回200 |
| 终端脚本不适合直接导入 | 顶层交互循环会阻塞服务 | 隔离测试入口，接口负责传入消息与会话配置 |
| 回答出现销量排序和库存承诺 | 提示词要求超出工具能力 | 已识别限制，尚需回归；不能凭部分结果判断完整目录或现货 |

### 技术收获
- 工具注册、模型发起调用和实际执行是不同阶段；通过完整消息中的调用记录及 ToolMessage 判断执行情况。
- config 关联会话，checkpointer 保存状态；session_id 不是用户ID或访问凭据。
- 内存检查点随进程结束而丢失，不支持跨进程共享。
- invoke() 返回完整状态，stream() 产生迭代结果；HTTP 流式输出需要另外设计响应传输。
- 路由负责 HTTP 输入输出，Agent 负责模型与工具编排，schema 负责数据约定。
- 服务启动、接口成功和推荐正确是不同验证层次，需要分别检查。

## 2026-10-22｜PostgreSQL 会话持久化接入与验证

### 已完成
- 通过独立 SSH 隧道连接服务器 PostgreSQL；Python 使用项目账号连接项目库，凭据仅保存在本地环境配置。
- 使用 PostgresSaver.setup() 初始化 checkpoint_migrations、checkpoints、checkpoint_blobs、checkpoint_writes 四张表。
- 创建同步连接池，配置 autocommit=True、row_factory=dict_row；通过 FastAPI lifespan 打开、等待就绪并在关闭时释放连接。
- 将 Agent 改为 create_recommendation_agent(checkpointer) 工厂函数，由外部决定记忆实现。
- 服务启动时使用 PostgresSaver(pool) 创建数据库版 Agent，保存到 app.state；对话路由从应用状态获取并使用 session_id 作为 thread_id。
- 根据用户确认的重启步骤及响应截图，同一会话重启后准确恢复测试编号 SC-742、直剪及7寸，基础持久化恢复验证通过。
- 两个已有会话表现出各自历史：pg_test02 恢复测试编号，pg_test01 保留原选购条件但没有该编号。

### 关键问题与处理
| 问题 | 处理与结论 |
|---|---|
| 初始化时报 public schema 权限不足 | 管理员在项目库授予项目账号 USAGE、CREATE 后完成初始化，无需超级权限；是否已撤销临时建表权限尚未核实 |
| 连接池启动超时 | 检查隧道和数据库连通性，随后启动日志确认连接池就绪；隧道需独立保持运行 |
| 数据库资源与 Agent 创建顺序 | 用工厂函数及 lifespan 明确先打开连接池、后创建保存器和 Agent，关闭时统一释放 |
| 编辑器提示连接池行类型不匹配 | 实际已设置 dict_row，类型声明仍待完善，区分静态提示与运行配置 |

### 技术收获
- 检查点保存会话执行状态，不等于向量检索或长期用户偏好库；当前无需 pgvector。
- schema 建表权限与连接、读写权限不同，初始化和日常运行应分阶段授权。
- lifespan 管理应用资源生命周期，不是请求中间件；接口不应每轮重新初始化表或连接池。
- HTTP 接口使用 PostgreSQL；独立终端测试仍使用 InMemorySaver，两者的记忆生命周期不同。

### 验证边界与待办
- 已有会话的结果符合历史区分预期，但未完成全新会话隔离用例；按用户要求不继续测试，不宣称完整隔离或授权验证通过。
- session_id 尚未绑定用户身份，持久化不替代访问控制；并发、历史裁剪、保留期限和备份策略待完善。
- 终端测试当前未传 thread_id 配置，独立运行仍需补齐；HTTP 路由已传入配置。
- 仍使用测试商品，不代表正式推荐验收通过；商品参数 schema 绑定、分页与库存能力待完善。

1. 整理本次改动并提交 Git，由用户自行执行。
