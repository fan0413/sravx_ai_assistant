### 学到的内容
- 模型负责理解需求和提出工具调用；程序负责校验与执行查询。
- Harness 是管理模型和工具运行的程序，不等于某一个框架。
- 上架不等于有货；起售价不等于指定规格价格。
- 接口接受参数不代表参数一定生效，需要查看实际实现及功能开关。
- Agent 以消息状态组织调用；工具参数 schema、函数签名和实际请求需保持一致。
- 参数校验必须绑定实际工具入口，仅定义数据类不代表约束已生效。
- 模型客户端初始化、发送请求、Agent 运行和工具执行是不同步骤；只有实际调用才证明对应链路可用。
- 非流式 invoke 与流式 stream 不同；流式模型输出还需要服务端向前端转发才能形成用户端流式体验。

### 技术收获
- 工具定义、注册和执行是不同环节；最终回答不带 tool_calls 并不代表未调用，应检查完整消息中的工具请求及 ToolMessage。
- config 指定会话归属，checkpointer 保存状态；只传 config 不会自动产生记忆。
- 内存检查点只在当前进程存活期间保留状态，程序重启后不能恢复。
- 工具返回成功不等于商品适合推荐；测试标记、价格口径、分页范围与库存能力仍须单独判断。

### 验证范围与待办
- 工具调用及多轮表现依据用户提供的运行日志；本次日志更新仅检查本地文件，没有重新调用模型或商品接口。
- 当前源码仍为 `@tool`，Product 参数类尚未绑定 args_schema；长度限制为100，与后端80字符口径不一致，参数边界测试未确认完成。
- 终端循环仍在模块顶层。接 FastAPI 前需移入 `if __name__ == "__main__":`，避免导入时等待输入。
- 固定会话 test01 仅用于本地测试；尚未验证多会话隔离、历史裁剪、持久化或并发请求。
- 查询仍只取第一页最多5条，不能据此判断完整目录、销量排名或现货情况；正式商品隔离和规格库存核验留待真实推荐阶段。
- FastAPI 对话接口、前端页面和流式响应尚未实现；技术说明中的旧阶段状态需在后续整理时同步。
