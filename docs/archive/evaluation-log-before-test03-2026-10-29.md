# Agent 评测记录

用于记录固定业务题目的基线、问题定位、优化方案与复测结果。LangSmith 保存具体运行证据，本文保存配置、判断依据与结论。学习开发日志只概括过程，技术文档解释实现。

## 记录规则

- 区分代码检查、用户提供的实验结果与实际执行验证，不将工具请求记录等同于执行成功。
- 按语义人工评分，不通过关键词出现与否判断回答对错。
- 脚本异常、输入字段错误等运行不计入回答质量基线。
- 记录数据集版本、代码版本和未提交修改；仅有 Git 提交号不足以复现未提交代码。
- 不记录密钥、真实客户资料或完整敏感调用日志。

### 评分标准

每项 0 或 1 分：工具选择正确、事实正确、边界准确、回答有效。任何无依据的附加断言也参与评分，不能只检查参考答案的必答点。事实评分以当前本地品牌知识库为参考，不等于重新审核全部外部材料来源。

编造参数、认证、库存或跨会话泄漏等问题另标严重失败，不被总分抵消。回复冗长先记录为体验问题；后续若增加长度指标，应作为新评分版本，不能悄悄改变基线口径。

### 拟优化方案（未验证）

第一轮只调整提示词，保持模型、知识内容和检索参数不变，方便归因。当前源码尚未包含下列新增规则；是否带来改善必须复测。

1. 简单知识题先直接回答，默认 2～4 句话；不主动展开无关成分、硬度或完整评级，详细比较题允许展开。
2. 保留证据确定程度：“没有依据”“不保证”“不能据此判断”不得改写为确定不存在或确定不能。
3. 养护、消毒操作同样要求检索依据和适用边界，不自行补充无依据的具体做法。
4. 首次检索足够回答就作答，只有关键依据缺失或冲突时才补充检索；不设置盲目的单次检索硬限制。

此阶段不需要引入中间件。若后续需要统一工具调用预算或拦截规则，再考虑 Agent 中间件，并说明引入理由。

### 复测安排

- 新实验建议使用前缀 `sravx-prompt-v2`，仍跑 K01、K02、K03、K05、K06；当前脚本仅选择后四题，复测前需将 K01 加回。
- 保留相同题目与评分规则，同时记录字数、工具请求次数与总耗时作为观察指标，不以回复变短单独判断成功。
- 优先确认 K05 边界错误消失、其余题不退步，再分析 K01 的召回片段与重复检索。
- 记录本地代码提交或源码快照、云端数据集版本与实验链接；基线没有完整快照的限制必须保留。
- 本轮每题只运行一次，后续按费用预算决定是否重复运行以观察波动。
- 完成知识题优化后再增加商品固定数据、多轮记忆、空结果与工具失败用例。

首轮知识题基线已收集并完成人工初评。系列与材料核心问答大体符合本地资料，但存在限定条件改写、回复冗长和重复检索问题。提示词优化与复测尚未完成，不能记录为已提升准确率或效率。
